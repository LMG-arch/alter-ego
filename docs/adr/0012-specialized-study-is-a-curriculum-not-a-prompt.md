## 背景

需求是：

> 写一个专项深入学习插件，比如角色是研究生，就随着时间的推移学习他相关专业的知识，
> 是工作了，也会自主的学习相关工作专业方面的知识，学习成果保存在 obsidian 的
> 知识库里面，讨论专业知识的时候会自动调用。

这句话里藏着四个必须先回答的问题，每一个的默认做法都会坏在一处不显眼的地方。

### 问题一：「相关专业」从哪来

人设表里只有一个自由文本字段 `occupation`（真实数据是「算法工程师」）。
从它到「该学哪些题」之间有两个选择：

| 做法 | 坏在哪 |
| --- | --- |
| 让模型自己决定学什么 | 每次问都得到不同的答案 → 「昨天学到哪」没有答案（违反 P6） |
| 让人设里再写一份大纲 | 用户被要求手写教学大纲，而这是**产品该干的活** |

### 问题二：「懂了」和「学过」是两件事

如果一次学完，角色不会经历「昨天还不知道」。而**这个功能存在的全部理由**，
就是那种「我一个星期前还不懂这个」的时间感。一次学完等于没有学。

### 问题三：「聊到专业时自动调用」最容易做成一句提示词

最省事的做法是在 `chat_reply.md` 里加一句「如果对方聊到你的专业，就把你学过的内容说出来」。
**这是 P3 明确禁止的形状**：机制约束优于提示词祈祷。

它的失效方式很典型——不报错、不崩溃，只是「有时候它会想起来，有时候不会」。
而 `docs/DESIGN.md` § 3 里写着：角色说了什么，必须能答上「它为什么这么说」。
一句提示词给出的答案是「模型决定说」，那不是答案。

### 问题四：`kernel/config.py` 只剩 2 行

`kernel/config.py` 是 **898 行**，而红线是「单文件 ≤ 900 行」（第 23 项）。
加一个 `[study]` 段（dataclass + 挂到 `Config`）需要 15 行以上。
**这个约束不是可以变通的：它是被 `scripts/check_architecture.sh` 和 CI 卡住的硬红线。**

### 约束

1. **课程表必须可复现**（P6）：同样的输入，同样的题，同样的顺序。
2. **召回必须是机制，不是祈祷**（P3）：「它怎么突然说起这个」要有确定答案。
3. **不引入新依赖**（P5）：中文分词不能靠 `jieba`——它已经是可选的
   `plugins/tokenizer_jieba`，而这一层的输出必须在任何环境下逐字节一致。
4. **`kernel/` 不得引用上层**（P1 / 红线第 4 组）：`kernel/config_study.py` 只能认识 `errors`。
5. **不新开 LLM 路由段**：`[llm.routing]` 在 `config.py` 里，加键同样撞 900 行红线。

## 决策

### 一、课程表是**算出来的**：领域表 + 五个角度 + 轮次

`domain/study.py::curriculum(field, rounds=...)` 是纯函数，输出**定长有序**的题目列表：

```
领域（14 个之一）×  角度（5 个固定）×  轮次（第 N 轮）
```

五个角度是固定的，写死在 `ASPECTS` 里：

| 角度 | 它挡住的失败方式 |
| --- | --- |
| 是什么 | 只会用不会解释 |
| 怎么做 | 只会背定义，动手就慌 |
| 容易踩的坑 | 把教科书当现实 |
| 和什么容易混 | 概念之间没有边界 |
| 我还不服的 | 只接受结论、不质疑 |

**「我还不服的」这一条是设计里最要紧的一格。** 一个只会复述的角色，
和一个会挑刺的角色，读起来完全是两种人；而挑刺是**可以被安排出来的**，
只要你给它留一格。

领域识别只看**一个信息源**：`[study] field` 优先，否则从 `occupation` 里
做子串匹配（`resolve_field`）。**认不出来就返回 `None`，不猜。**
CLI 会明确说「不知道该学什么」，而不是随机挑一个方向——瞎猜一个方向的后果是
它写出一堆像模像样的空话，而没人会想到去检查。

### 二、一次学一格

`alterego study next` 默认学 `[study] rounds` 格，而它是**格数，不是轮数**
（一轮 = 五个角度全部走完）。默认值 1。

进度记在 `00-索引/.study-state.json`，用**已完成主题的 key 集合**表达，
不记「学到第几轮第几个」：

```json
{ "done": ["data/1/是什么"], "field_key": "data", "last_at": "2026-09-16T21:40:00+08:00" }
```

**记集合而不是记指针，是为了幂等。** 同一格学两次不会让进度前进两格；
中途删掉一篇文章，重建的进度也不会错位。

### 三、召回是纯函数评分，不是提示词

`domain/study.py::select(notes, query=..., limit=..., min_score=...)` 是**唯一**一条
从「一句人话」到「几篇笔记」的通道，纯函数、无 IO、无时钟。

- 切词：拉丁词（≥2 字符）+ **中文二字组**。`jitaba` 之类的分词器一律不用（P5、P6）
- 打分：标题命中 ×3、标签 ×2、正文 ×1，再按正文长度开方衰减
- 排序：分数降序，**同分按路径升序**（P6：不能依赖字典序不确定的迭代）
- 门槛：`[study] min_score`（默认 2.0）。**低于门槛就不算命中。**

分数与命中的词一起返回，所以 CLI 能直接回答「为什么是这几篇」。

### 四、**虚词必须挡掉**：这是本文档里唯一一条被测试逼出来的决定

字组切词的第一版没有虚词表，于是：

```
标题「降维是什么」→ 二字组里有「什么」
问句「今晚吃什么」→ 二字组里也有「什么」
→ 标题命中 3 分 ÷ 衰减 ≈ 2.94 ≥ 门槛 2.0 → 命中
```

而**第一轮的全部题目都以「是什么」结尾**（五个角度里的第一个）。
后果是：任何一句带「什么」的话——「今天吃什么」「你说什么」「为什么」——
都会翻出全部第一轮的专业笔记。门槛形同虚设。

**修法是把虚词从词表里去掉，而不是把门槛调高。** 调高门槛会同时杀掉
「单次标题命中」这种合法情况（3.0 分），那是把一个真实信号和一个噪声信号
用同一个旋钮一起拧掉。挡掉虚词则只动噪声那一侧，而且仍然是纯函数。

`_STOPWORDS` 因此是 `domain/study.py` 里的模块级常量（`什么` `怎么` `这个`
`可以` `这时候`……），顺序无关、环境无关。

**这条决定写进 ADR 是因为它容易被「简化」掉。** 一个看起来只有二十几个词的表，
很容易被认为是多余的，直到有人删掉它、然后在真实使用里发现
「它怎么每次聊天都在说专业的事」。

### 五、笔记写进**已有**的 Obsidian 知识库，布局加一层 `60-专业`

不另开一个目录。原因是**链接**：专业笔记要能和「50-见过的人」「40-记忆」互相引用，
分开两个库之后 Obsidian 的双链就断成两半。

新增的文件夹插在 `50-见过的人` 与 `99-收集箱` 之间：

```
00-索引  10-日程  20-想法  30-读到  40-记忆  50-见过的人  60-专业  99-收集箱
```

文件名由**标题**决定（`slugify(topic.title)`），所以同一格重跑两次落成同一个文件——
**幂等靠这个，而不是靠「记得自己写过什么」**。

`60-专业` 加入 `CONTENT_FOLDERS`（所以它有索引页、也参与孤儿与断链校验），
同时 `sim/vault.py::write_note` 从 `_write` 改成公开：那一对性质——
**原子写（先写 `.tmp` 再 replace）、不碰换行符**——正是「复制一份」最容易漏掉的东西，
宁可共用。

### 六、复用 `vault` 这条 LLM 路由，不新增段

`sim/study.py` 用的是 `PURPOSE = "vault"`。理由有两条：

1. `[llm.routing]` 的表在 `kernel/config.py` 里，加一个键**同样撞 900 行红线**。
2. 这次调用的**形状和整理知识库完全一样**：给一段材料、要一段 JSON、温度偏低。

因此这次调用与 `vault_organize` 共享同一条路由与同一个预算。**代价写在下面。**

### 七、`StudyConfig` 进 `kernel/config_study.py`，不进 `config.py`

这是**执行既有红线**，不是新的架构决定。先例是 `kernel/config_values.py`。
`config.py` 已经 898/900；加一个 `[study]` 段必然越界。

新卫星模块只允许引用 `kernel/errors.py`（第 4 组红线：`kernel/` 不得引用任何上层模块）。

### 八、入口是 CLI，不是插件

需求里写的是「插件」，但**实现成了第六个组装根**，没有 `plugins/study/`。
理由是红线：一个插件要自己开数据库、自己读配置、自己调模型，
而这正好撞上第 3 组（插件不得直接连数据库）与第 21 组（`capabilities/` 不得直连 LLM 端点）
的红线精神——今天的内核没有给插件「一个已经装好的网关 + 一条只读的内容连接」。

**「插件式」在这个项目里的真实含义是「能加而不必改内核」，而不是「必须叫插件」。**
`StudyWorkbench` 是一个 `frozen` 数据类，`learn()` / `plan()` / `recall()` 是它的自由函数；
将来内核提供了合适的扩展点，把它们包一层 `Plugin` 即可，**领域层一行都不用改**。

## 后果

### 好的

- 课程表可复现：「上次学到哪」有确定答案，`study plan` 能把接下来的题印出来
- 召回可解释：每条命中都带分数与命中的词，CLI 直接打印
- 零新依赖，零新表，零新迁移
- 专业笔记与其它笔记**在同一个 `vault` 里互相链接**，Obsidian 里是一张图
- 一格失败不记进度：坏回复只报「没写成」，下次还会来（这是最难发现的错，所以专门测了）

### 坏的 / 要接受的

- **和 `vault` 共用一条路由、共用一份预算。** 想给学习单独配一个便宜模型的人
  只能改 `[llm.routing] vault`，而那会同时影响知识库整理。
- **领域识别是子串匹配，会认错。** 「数据分析师」能认出来，「搞数据的」认不出来。
  缓解办法：`[study] field` 可以手填，且**它优先**。这一点写进 CLI 输出，
  不让用户靠猜。
- **二字组召回是粗的。** 「神经网络」切成「神经/经网/网络」，靠更多命中补齐。
  它换来的是「任何环境下逐字节一致」，代价是偶尔会有一两条不好不坏的命中
  （见决策四）。
- **`rounds` 这个名字指的是「格数」不是「轮数」**，而 `Topic.round` / `Progress.rounds_done`
  指的是轮数。同一个词两个意思，是这套命名留下的疤。改名的代价（模板、配置测试、
  文档、所有引用的 docstring）大于收益，所以**留疤但写清楚**。
- **认不出领域时 `kernel/config.py` 的 `[study] field` 是唯一的补救入口**，
  所以它必须一直被 CLI 提示出来。

## 备选方案

| 方案 | 为什么不选 |
| --- | --- |
| A · 让模型每次决定学什么 | 不可复现，P6；「上次学到哪」没有答案 |
| B · 人设里再存一份学习大纲 | 把写大纲的活推给用户，而那正是产品该做的 |
| C · 一次学完整个领域 | 「昨天还不知道」这个时间感消失，功能失去理由 |
| D · 在 `chat_reply.md` 里加一句「聊到专业就说出来」 | P3 明令禁止；失败方式是静默的「有时候想不起来」 |
| E · 用 `jieba` 分词做召回 | 引入新依赖（P5），且输出随版本变化（P6） |
| F · 提高 `min_score` 挡住虚词噪声 | 同一个旋钮同时拧掉真实信号（单次标题命中）；见决策四 |
| G · 召回用 IDF / 词频统计 | 输出依赖整个库的内容 → 改一篇文章会改变另一篇的召回，违反 P6 |
| H · 另开一个「专业库」目录 | Obsidian 双链断成两半，专业笔记无法与被记住的人互相引用 |
| I · 给 `[llm.routing]` 加一个 `study` 键 | 撞 900 行红线；且这次调用的形状与 `vault` 完全一致 |
| J · 把 `[study]` 段塞进 `kernel/config.py` | 同上；先例是把卫星段放进 `config_values.py` |
| K · 做成 `plugins/study/` | 插件拿不到「已装好的网关 + 只读内容连接」，会撞红线精神；见决策八 |

## 什么时候应该重新审视

- **内核插件 API 提供了「已装好的网关 + 只读内容连接」**：那时决策八可以改成插件，
  领域层不用动。
- **`kernel/config.py` 拆成多文件**：那时决策七的卫星模块可以并回去，
  `[llm.routing]` 也可以有自己的 `study` 键（决策六）。
- **`min_score` 的门槛在真实使用里被频繁调**：说明打分公式本身需要改，
  而不是继续加虚词（决策四只解决了一类噪声，不是全部）。
