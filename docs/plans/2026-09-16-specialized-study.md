# 计划 · 专项深入学习（`alterego study`）

> 决策记录见 [ADR-0012](../adr/0012-specialized-study-is-a-curriculum-not-a-prompt.md)。
> 本文件是落地细节与**结果**。

---

## 1. 原话与读法

> 写一个专项深入学习插件，比如角色是研究生，就随着时间的推移学习他相关专业的知识，
> 是工作了，也会自主的学习相关工作专业方面的知识，学习成果保存在 obsidian 的知识库里面，
> 讨论专业知识的时候会自动调用

拆成五条可验证要求：

| # | 要求 | 本批次怎么满足 |
| --- | --- | --- |
| R1 | **专项**：有明确的方向 | `[study] field`，留空时从人设的 `occupation` 认（§ 2） |
| R2 | **随着时间推移**：不是一个瞬间 | 课程表算成一格一格，`next` 默认一次只学一格（§ 3） |
| R3 | **自主学习**：没人教也会去学 | `next` 不依赖对方先开口；题面由代码算出，不等人出题 |
| R4 | **成果存进 Obsidian 知识库** | 写进 `60-专业/`，与「见过的人」「记忆」同一个库（§ 5） |
| R5 | **聊到专业时自动调用** | `select()` 纯函数打分 + 门槛，进 `chat_reply` 的上下文（§ 4） |

**「自动」的含义**：不是「后台偷偷跑」（那需要常驻调度器，见 § 7），
而是「不用人去点『现在学点什么』」——`alterego study next` 自己知道下一格是什么。

## 2. 领域识别

`domain/study.py::resolve_field(configured, *, occupation)`：**配置优先，其次认 occupation。**

内置 14 个领域（`_FIELDS`），每行是 `(显示名, 关键词, 键)`：

| 键 | 显示名 | 关键词举例 |
| --- | --- | --- |
| `data` | 数据与算法 | 算法、数据科学、数据分析、机器学习、人工智能、推荐系统 |
| `software` | 计算机软件 | 程序员、软件开发、软件工程、后端、前端、全栈、架构师 |
| `product` | 产品与设计 | 产品经理、产品设计、交互设计、用户体验、设计师、ui、ux |
| `growth` | 运营与增长 | 运营、市场、品牌、增长、新媒体、电商 |
| `finance` | 财务与会计 | 会计、财务、审计、税务、出纳、理财 |
| `law` | 法律 | 律师、法务、法律、合规 |
| `medical` | 医学与健康 | 医生、医师、护士、临床、药师、心理咨询 |
| `teaching` | 教育与科研 | 老师、教师、教授、讲师、教研、辅导员 |
| `civil` | 建筑与土木 | 建筑师、土木、结构工程、施工、造价、监理 |
| `hardware` | 制造与硬件 | 机械、电子、硬件、嵌入式、电气、自动化、工艺 |
| `media` | 传媒与内容 | 记者、编辑、文案、编导、主播、媒体 |
| `hr` | 人力资源 | hr、人力、招聘、人事、培训 |
| `sales` | 销售与客户 | 销售、客户经理、商务、客服 |
| `art` | 艺术与表演 | 演员、音乐、绘画、舞者、摄影、戏剧 |

**表序即优先级**：`"人力资源数据分析"` 同时含「人力」（第 12 行）与「数据」（第 1 行），
落在 `data`。这条顺序有测试盯着（`test_the_table_order_decides_ties`）。

三条边界行为：

1. **配置里填了就听配置的**，不再看 `occupation`。
2. **在读学生认不出专业**：`研究生` / `硕士` / `博士` … 命中 `_STUDENT_WORDS` 时，
   `field_hint()` 说的是「填你在学的那个专业」——专业名只有当事人知道，猜不得。
3. **什么都没有就是 `None`**，不编一个领域出来。瞎猜一个方向的后果是
   它写出一堆像模像样的空话，而没人会想到去检查。

## 3. 课程表

### 3.1 五个角度

`ASPECTS = ("是什么", "怎么做", "容易踩的坑", "和什么容易混", "我还不服的")`，**顺序即学习顺序**。

| 角度 | 它挡住的失败方式 |
| --- | --- |
| 是什么 | 只会用不会解释 |
| 怎么做 | 只会背定义，动手就慌 |
| 容易踩的坑 | 把教科书当现实 |
| 和什么容易混 | 概念之间没有边界 |
| 我还不服的 | 只接受结论、不质疑 |

「我还不服的」这一格是设计里最要紧的：一个只会复述的角色和一个会挑刺的角色
读起来是两种人，而**挑刺是可以被安排出来的**——只要给它留一格。

### 3.2 题面的形状

`curriculum(field, rounds=N)` 展开成 `field.label · aspect` 的定长有序表，
第 2 轮起题面带后缀 `（第 N 轮）`，主题键是 `{field.key}/{轮}/{角度}`：

```
数据与算法 · 是什么            key = data/1/是什么
数据与算法 · 怎么做            key = data/1/怎么做
数据与算法 · 容易踩的坑        key = data/1/容易踩的坑
数据与算法 · 和什么容易混      key = data/1/和什么容易混
数据与算法 · 我还不服的        key = data/1/我还不服的
数据与算法 · 是什么（第 2 轮）  key = data/2/是什么
```

### 3.3 一次学一格

`next_topics(field, progress=..., rounds=N)`：`rounds` 是**要几格**，不是轮数。

一句坑要记住：`[study] rounds = 1` 的意思是「一次学一格」。想让它一次走完一轮，
填 5。`next_topics` 里那个 `need = progress.rounds_done + rounds + 1` 里的 `+1`
是防「进度走到第 3 轮时表展开得不够远」——展开不够会返回空表，
而那时候真正该学的是第 4 轮。

### 3.4 进度

`00-索引/.study-state.json`（以点开头，Obsidian 不显示）：

```json
{
  "done": ["data/1/是什么", "data/1/怎么做"],
  "field_key": "data",
  "last_at": "2026-09-16T21:40:00+08:00"
}
```

- **记集合，不记指针**：`advance()` 幂等，同一格记两次还是一条；删掉一篇文章也不会错位。
- **换领域就清空**：`field_key` 对不上时进度按空处理（`parse_progress`）。
  两个专业的主题混在一个进度里，「学到第几个了」就没有意义了。
- **坏数据不报错**：进度只是缓存，最坏的结果是重学一格。
  为了它让 `study status` 跑不起来，正好发生在这个文件被改坏的时候。

## 4. 召回

### 4.1 切词

`terms(text)`：拉丁词（≥2 字符，保留 `+ # . _ -`）＋ 中文**二字组**。

```
terms("卷积神经网络 CNN") == ('cnn', '卷积', '积神', '神经', '经网', '网络')
```

不用 `jieba`：它是可选的 `plugins/tokenizer_jieba`，而这一层的输出必须在
任何环境下**逐字节一致**（P6）。二字组不需要词典。

### 4.2 虚词表 `_STOPWORDS`

第一轮题面全是 `X · 是什么`，于是 `什么` 这个二字组会撞上「今晚吃什么」
「你说什么」「为什么」——**每一句疑问句都翻出全部第一轮**。

修法是**丢掉虚词**，不是调高门槛：调高门槛会连「标题真的命中一次」（3.0 分）
一起杀掉，那是真信号。虚词表 60 个词，纯常量，顺序无关。

| | 拦住了 | 留住了 |
| --- | --- | --- |
| `今晚吃什么` | ✓ 一篇都不翻 | |
| `降维是什么` | | ✓ `是什` 命中标题 |
| `降维怎么做` | | ✓ `么做` 命中标题 |

「是什么」被丢掉 `什么` 之后还剩 `是什`，所以它对**真的在说这个词的人**仍然有效。

### 4.3 打分与门槛

`score_note(note, query_terms=...)`：标题 ×3、标签 ×2、正文 ×1，
再按正文规模阻尼 `damp = 1 + log10(1 + 词数/200)`。

`select(notes, query=..., limit=3, min_score=2.0)`：

- 排序 `(-score, path)`——**同分按路径**，不依赖输入顺序（`scan()` 的顺序会变）
- 门槛默认 `DEFAULT_MIN_SCORE = 2.0`，只碰得到一个词（1 分）不进
- 结果里带**命中的词**，所以 `alterego study recall` 能直接回答「为什么是这几篇」

### 4.4 进上下文

`render_context(recall, budget=900)` 拼出一块：

```
【我学过、可能和这次有关的】
- 数据与算法 · 是什么（60-专业/数据与算法 · 是什么.md）
  这一层把高维压到低维。
```

开头那句「这些是我自己写过的笔记，不是这次对话里对方说的话」不能省：
不写，模型会把它当成对方刚说的话接着答，**那比不调用更糟**。
预算不够就**整篇丢**，不给半篇——半篇会变成一句像结论的错话。

## 5. 落盘与进度

### 5.1 写进已有的那个库

不另开目录。专业笔记要能和「50-见过的人」「40-记忆」互相引用，
分开两个库 Obsidian 的双链就断成两半。布局中间插一层：

```
00-索引  10-日程  20-想法  30-读到  40-记忆  50-见过的人  60-专业  99-收集箱
```

`60-专业` 同时进了 `CONTENT_FOLDERS`，所以它有索引页、也参与孤儿与断链校验。

### 5.2 文件名由标题决定

`60-专业/{slugify(topic.title)}.md`，例如 `60-专业/数据与算法 · 是什么.md`。
**同一格重跑两次落成同一个文件**——幂等靠这个，不靠「记得自己写过什么」。

### 5.3 正文骨架

```
## 一句话      ← summary
## 记下来的    ← points（至少一条，否则整篇判为失败）
## 我还不确定的 ← unsure（模型不写就没有这一节）
## 出处        ← 领域 / 第几轮 / 「这是我自己学的，不是谁教我的」
```

### 5.4 失败不记进度

模型给不出结构完整的 JSON（要 `summary` + ≥1 条 `points`）时：
记一条 `failed`、写一条 warning、**`continue`，不推进进度**。
下次还会来学这一格——这是最容易被忽略、也最难发现的一类错，所以专门测了。

### 5.5 收尾

学完至少一格之后：`build(work, now=now)` 重建索引与目录页，
再 `_save_progress(advance(...))` 落盘，最后 `logger.info` 一条。

## 6. CLI

```
alterego study {next,plan,recall,status}
```

| 命令 | 花钱 | 做什么 |
| --- | --- | --- |
| `status` | 否 | 学到哪了、库里有什么、有没有笔记没进索引 |
| `plan [--rounds N]` | 否 | 接下来 N 格是哪几个题面 |
| `recall 一句话 [--limit N] [--min-score F]` | 否 | 给一句话，看它会翻出哪几篇（带命中的词） |
| `next [--rounds N] [--dry-run]` | **是** | 真的学几格，写进 `60-专业` |

三个不花钱的命令**不需要任何密钥**就能跑——这是有意的：
配不出模型的人也得能看见这个功能在干什么。`next --dry-run` 同理，
它只印出「这次会学哪几格」，不调模型、不写文件。

**`next` 只在真的要调模型时才去建供应商。** 先用一个空注册处
建一个探测用的 workbench 认领域；认不出领域 → `learn()` 会直接返回「跳过」，
一行都不写，那一步**不该**要求用户先填密钥。

输出里的对齐用 `cli_io._pad`（按东亚字符宽度算），直接 `ljust` 会让中文列歪。

## 7. 本批次**不做**的（写清楚，免得下一轮当成 bug）

| 不做 | 为什么 |
| --- | --- |
| 把业务逻辑做成 `plugins/study/` | 插件只被允许 import 契约与内核门面，拿不到「已装好的存储连接」（ADR-0012 决策八） |
| 常驻调度器到点自动学 | `sim/` 主体还没跑起来；现在由 `alterego study next` 触发 |
| 自动把召回塞进每一轮对话 | 调用点在 `sim/` 的对话流程里，本批次只把 `recall()` 这个机制备好 |
| 每个领域独立的子目录 | 文件名已经带领域名；多一层目录只会让 Obsidian 的图更难读 |
| 学习的「掌握度」评分 | 没有可验证的判据。编一个 0–100 的分数只会变成装饰 |
| `[llm.routing] study` 单独一段 | 撞 900 行红线，且调用形状与 `vault` 一致（ADR-0012 决策六） |

```powershell
# 认领域、印题面、不开密钥
$env:PYTHONPATH='src'; python .git/smoke_study.py

# 单元 + 行为
python -m pytest tests/test_domain_study.py tests/test_sim_study.py tests/test_cli_study.py -q
```

实测（2026-09-16）：

| 测试 | 结果 | 覆盖率 |
| --- | --- | --- |
| `test_domain_study.py` | 143 passed | `domain/study.py` 100.00% |
| `test_sim_study.py` | 57 passed | `sim/study.py` 100.00% |
| `test_cli_study.py` | 52 passed | `cli_study.py` 96.39% |
| `test_kernel_config.py` 的 `[study]` 段 | 11 passed（该文件 90） | `kernel/config_study.py` 100.00% |

全量：**2397 passed + 1 skipped**（共 2398 个测试），全局覆盖率 **96.45%**，
四道覆盖率下限全过（`alterego` 96.45% / `kernel` 96.84% / `domain` 98.48% /
`sim` 96.51%），架构红线 23/23。

**`test_kernel_config.py` 那 11 条不是补数字。** 卫星模块的
`__post_init__` 是两处只有坏配置才走到的分支，全库跑完它们一次都没被执行过：
`rounds = 0` 会让 `study next` 什么都不学却报告成功（静默空转），
`min_score = -1` 比 0 还松、等于每轮都硬塞专业笔记。
`rounds = true` 单独测一次，因为 Python 里它就是 `1`——
不特判的话会被静默接受，而用户看到的是「学到了」。

真实输出（人设「林晚 · 算法工程师」）：

```
人设      林晚（p1）
库        D:\ai\个人agent\exports\林晚的知识库
领域      数据与算法（从 occupation 认出来的：算法工程师）
进度      0 格（第 0 轮学满）
上次      （还没学过）
笔记      0 篇
```

```
接下来 3 格：
  1. 数据与算法 · 是什么
  2. 数据与算法 · 怎么做
  3. 数据与算法 · 容易踩的坑
```

## 9. 落地时与原计划的偏差

| 计划 | 实际 | 为什么改 |
| --- | --- | --- |
| 用 `_STOPWORDS` 挡虚词（第一版打算靠 `min_score`） | **两个都做，但主责是虚词表** | 一开始决定「保持粗行为 + 用门槛」并有测试钉住；写完测试发现门槛拦不住它——`什么` 撞的是**标题**（3.0 分），比门槛高。于是补上虚词表，并把那条测试反过来说 |
| `capability.study` 插件 | 第六个组装根 `cli_study.py`，**外加一个只声明的 `plugins/study/`** | 这是两件事：业务逻辑不能住进插件（红线），但这个功能该有一条自己的清单项——详见 ADR-0012 决策八 |
| `[study]` 段放进 `kernel/config.py` | 卫星模块 `kernel/config_study.py` | `config.py` 898 行，红线是 900 |
| `rounds` 表示轮数 | 表示**格数** | 一次学一格才叫「随着时间推移」；名字留下了疤，写进了 `config_study.py` 的 docstring |
