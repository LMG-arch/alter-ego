# Obsidian 知识库

角色的知识库。它自己把日程、看到的东西、想到的事写进去，自己归类，自己互链。

用 [Obsidian](https://obsidian.md) 打开库目录就能看到——不用装任何插件，
不用装 Dataview，甚至不用 Obsidian：它就是一个装满 `.md` 的文件夹。

## 装

把 `plugins/obsidian_vault` 拷到插件搜索路径下（默认是项目里的 `plugins/`
或 `~/.alterego/plugins/`），然后在 `config/alterego.toml` 里加：

```toml
[plugins]
enabled = ["capability.obsidian_vault"]
```

它是 `capability` 插件，`enabled_by_default = false` —— 不主动往别人实例里塞东西。

## 配置

| 键 | 类型 | 默认 | 说明 |
| --- | --- | --- | --- |
| `vault_path` | string | `""` | 库建在哪。**留空**表示交给 `alterego vault` 按角色名决定（`exports/<角色名>的知识库`） |

改完 `vault_path` 立即生效（`auto_reload = true`），不用重启。

只有一项配置，因为只有一项真的会改变行为。想加「同步开关」「整理开关」
之前先问一句：这是配置，还是应该做成另一个插件？（设计原则 P4）

## 用

```bash
alterego vault init          # 把库搭起来：目录、.obsidian、索引页
alterego vault sync          # 库里的日程 / 想法 / 搜集到的 → 笔记（不花钱）
alterego vault organize      # 让角色自己把收集箱里的东西归位（花一次调用）
alterego vault organize --dry-run   # 先看看收集箱里有什么，不花钱
alterego vault status        # 现在库里什么样，有没有坏链
```

第一次用：`init` → `sync` → `organize`。

## 库长什么样

```
<角色名>的知识库/
├── 00-索引/            总索引、每个目录的索引页
│   ├── <角色名>的知识库.md
│   ├── 日程.md
│   ├── 想法.md
│   └── ...
├── 10-日程/            每天一页：打算做什么、实际做了什么
├── 20-想法/            它自己想到的
├── 30-读到的/          搜集来的链接和摘要
├── 40-记得的事/        记忆里还算清楚的
├── 50-见过的人/        认识的人
├── 99-收集箱/          素材暂存区，等它自己归类
└── .obsidian/          Obsidian 的配置，本插件生成的
```

数字前缀是**故意的**：Obsidian 的文件树永远按这个顺序排，
不依赖排序设置，不依赖用户手动拖——换个编辑器打开也一样。

## 三步的分工

| 命令 | 干什么 | 花钱吗 | 会失败吗 |
| --- | --- | --- | --- |
| `sync` | 结构化数据 → Markdown | **不花** | 不会，纯渲染 |
| `organize` | 收集箱 → 该去的目录 | 花一次 | 会，模型可以胡说 |
| `build` | 按实际文件重算索引 | **不花** | 不会，纯推导 |

**第一步永远免费、永远成功。** 哪怕模型配额用光、API 挂了，
它照样每天有自己的日程页。真正的「它自己在整理」在第二步。

代码管骨架，角色管分类：

- **代码保证**：目录结构、frontmatter 字段、索引页、坏链检查、原子写入；
- **角色决定**：这条素材归哪个目录、叫什么名字、打什么标签、和哪些笔记互链。

## 四条不变量

「条理清晰」不是形容词，是四条能自动检查的规矩：

1. 每篇都有 frontmatter（`title` / `type` / `created` / `tags`）
2. 每个 `[[链接]]` 都指向存在的笔记
3. 没有重名的笔记（`[[阿哲]]` 不该有歧义）
4. 每篇笔记都被它所在目录的索引页覆盖

`alterego vault status` 会把这些报出来。

## 它和角色的记忆有什么关系

**知识库是库的下游，从不往回写。**

日程、行为日志、搜集到的信息、记忆——都从数据库单向流进 Markdown。
这条很要紧：一旦允许回写，「用户手改了一个 Markdown 文件」就得有冲突解决
策略，而那个策略没人会记得去维护。想看角色**真的**记着什么，
`alterego memory` 那边才是源。

## 用户也能往里扔东西

`.obsidian/app.json` 里把「新建笔记的位置」设成了 `99-收集箱/`。
你在 Obsidian 里随手 Ctrl+N 写一行，下次角色 `organize` 时会顺手把它归位。

共用一个入口，比教你「请把东西放到 99-收集箱」实际得多。

## 它不做什么

- **不装 Obsidian 插件**。库是纯 Markdown，Dataview、Canvas、图片附件都没有用上。
- **不做双向同步**。见上面「知识库是库的下游」。
- **不在 tick 里跑**。`intent_types` 是空的——整理一次是几十秒的批处理，
  不是 30 秒的 tick 里该做的事。
